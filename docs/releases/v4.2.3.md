# Tracegate 4.2.3

Telemt unit fix. No database migration and no change to issued
connections.

- `tracegate-mtproto@.service` mounts only the Telemt runtime directory
  into the container instead of the whole MTProto state directory. Newer
  Telemt images open every parent of `--data-path`; the state directory is
  root-owned with mode 0711, so the nonroot container user got EACCES
  ("Can't use runtime directory") on start and the engine updater rolled
  the image back. The container also no longer sees the control-plane
  state files kept beside the runtime directory.

## Upgrade notes

- Only hosts that run Telemt (Endpoint) are affected; Entry may stay on
  4.2.2 or be upgraded at any time.
- Deploying restarts Telemt once. Telemt candidates rejected before the
  upgrade can then be approved again with `tracegate-engine-update`.

Validated by lint, host checks, the public release privacy check and the
unit-file tests; the new image was started with the runtime-only mount and
a 0711 parent before release. The full test suite runs in CI.
