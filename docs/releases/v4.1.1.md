# Tracegate 4.1.1

Fixes found after the 4.0.0 rollout. One database migration.

- **Hysteria2 links import everywhere.** The host part of the link always
  carries the single listener port; the port-hopping range is in the `mport`
  query parameter with `mportHopInt`. Clients that support hopping read it;
  the others connect to the listener port. Re-issue a hopping profile to get
  the new link; the server side is unchanged.
- **Chain Hysteria cap 15 Mbit/s** per client by default
  (`HYSTERIA_CHAIN_CLIENT_MAX_MBIT`), used consistently by issuance, the
  Entry server bandwidth and the Entry login check.
- **WebSocket and gRPC client families removed.** Migration `d4b6f0e2a315`
  revokes every remaining connection; they can no longer be issued,
  re-issued or exported, and the bot no longer offers them. Own-domain TLS,
  the cover site and Grafana are unchanged.

## Upgrade notes

- Deploy Entry first, then Endpoint (the migration runs there).
- On Entry, set `HYSTERIA_CHAIN_CLIENT_MAX_MBIT` to the wanted cap before or
  with the deploy if it is set explicitly in the runtime environment.
- After the deploy, users of WebSocket or gRPC profiles need a Reality,
  Chain or Hysteria profile instead.
- 4.1.0 notes (engine update supervisor, deploy fixes) apply when upgrading
  from 4.0.0.

Validated by the test suite (including the PostgreSQL migration tests), lint,
host checks and the public release privacy check.
