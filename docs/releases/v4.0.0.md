# Tracegate 4.0.0

First release of the Tracegate 4 line. It hardens engine updates, alerting and
the public port model on the existing control plane. The pull-based
desired-state agent planned for Tracegate 4 is not part of this release.

- **Engines never pull at start.** Every engine unit starts the image recorded
  by digest in the local artifact store and is checked by a read-only pre-start
  verifier. `tracegate-host-deploy deploy` captures the running digests and
  verifies the store before it changes anything. Operator CLI:
  `tracegate-artifacts`.
- **Three-state alerts.** Missing metrics and failed queries are reported as
  "no data" and "query error", never as service failure. A new warning names
  the backhaul channel whose probe metrics are missing. Takes effect after the
  Grafana bootstrap is re-run.
- **Removed client families.** WireGuard over WebSocket and the client
  Shadowsocks-2022 + ShadowTLS profile can no longer be issued; migration
  `c3a5e9d1f204` revokes the remaining rows and the next deploy removes their
  units. The Entry-to-Endpoint backhaul, which uses the same protocol pair, is
  unchanged and covered by a render-invariance test.
- **Port model.** Chain stays on TCP/443 only. Direct VLESS/REALITY revisions,
  including re-issues, use `REALITY_DIRECT_PORT` (default 8443); Endpoint
  serves TCP/443 and TCP/8443 and keeps every earlier profile working. Entry
  never listens on TCP/8443 outside the legacy MTProto fallback mode.
- **Telegram Proxy** is delivered only through Entry on TCP/443. Endpoint keeps
  routing the FakeTLS name on TCP/443 for backup links saved earlier while
  `MTPROTO_DIRECT_BACKUP_HOST` is set. Link messages ask users to keep the
  Telegram app current.
- **Hysteria2.** Port hopping for Direct revisions with a randomized hop
  interval; the Endpoint deploy generates private random ranges when none are
  configured. Certificate verification against the server name for new and
  re-issued revisions (`HYSTERIA_TLS_VERIFY`). Re-issue keeps the obfuscation
  chosen at creation.

## Upgrade notes

- Includes one additive migration (`c3a5e9d1f204`). Existing connection
  revisions, secrets and client formats are not rewritten; only the retired
  families are revoked.
- Before deploying Endpoint, confirm that any private `haproxy.cfg` or
  `nftables.conf` overlay carries the TCP/8443 bind and accept rule (the health
  check now requires `listen tcp/8443`), that no other service listens on UDP
  inside the generated hop bands (20000-31999), and that the Hysteria
  certificates are publicly trusted and cover the server name clients use.
- The first deploy on each host captures the running engine digests; the deploy
  aborts before any change if that is not possible.
- Re-run the Grafana bootstrap after the deploy to load the new alert rules.

This release was validated by the test suite, lint, host checks and the public
release privacy check. No transport is claimed to resist every inspection
technique; field acceptance is measured after deployment.
