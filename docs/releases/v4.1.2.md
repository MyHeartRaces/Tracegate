# Tracegate 4.1.2

Entry shaped around what it runs today. One database migration.

- **Entry Hysteria retired.** Chain is issued only as VLESS Reality. Entry no
  longer runs, renders or health-checks Hysteria, and the firewall template
  closes public UDP/443 on Entry. Migration `a8c3e5f17b42` revokes any
  remaining Chain Hysteria connection; it can no longer be issued, re-issued
  or exported. Direct Hysteria on Endpoint is unchanged.
- **Entry traffic cap enforced.** 65 Mbit/s for the whole Entry host in each
  direction by default (outgoing shaping, incoming policing), configured by
  `AGENT_ENTRY_TRAFFIC_SHAPING_*`. Endpoint is not shaped.
- **Leftovers removed.** Entry Xray template no longer carries the retired
  WebSocket/gRPC inbounds; the Entry -> Endpoint bridge is unchanged.
- **Housekeeping.** nginx `http2 on;`, `opentelemetry-api` 1.45.2, README.

## Upgrade notes

- Deploy Entry first, then Endpoint (the migration runs there).
- The deploy stops and disables `tracegate-hysteria@entry`. Keep the Entry
  Hysteria base config on disk until 4.1.2 is confirmed healthy: a rollback
  to 4.1.1 starts the unit again.
- Live hand-managed configs are not rewritten by the deploy: close UDP/443 in
  the live Entry firewall, and switch hand-managed nginx configs to
  `http2 on;`, as separate operator steps.

Validated by the test suite (including the PostgreSQL migration tests), lint,
host checks and the public release privacy check.
