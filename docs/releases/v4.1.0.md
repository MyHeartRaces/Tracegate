# Tracegate 4.1.0

Adds the engine update supervisor and the fixes found during the 4.0.0
rollout. No database migration.

- **Engine updates follow upstream, on evidence.** A daily job discovers new
  official engine images without pulling them, waits until a digest has stayed
  the newest for the soak period (three days by default), stages it by digest
  and runs the engine's own configuration check against the live
  configuration. It activates a candidate only where an authenticated probe
  set exists and passes, one unit at a time, with automatic rollback to the
  last good version on any failure. Where no such probe exists yet (Telemt,
  and Xray and Hysteria on Entry) the candidate is staged, checked and queued
  for the operator, who approves with one command. Major versions are never
  crossed automatically. A hold switch freezes all automatic activation.
- **Deploy fixes:** the artifact CLI reads the registry of the release being
  deployed; the Endpoint deploy loads the Hysteria port-hopping table itself;
  the RTC clock timer stays off where network time is synchronized.
- **Telegram Proxy** is routed only through Entry; Endpoint renders no MTProto
  route on its public listeners.

## Upgrade notes

- Deploy Entry, then Endpoint. Re-run the Grafana bootstrap and redeploy the
  API so the new update alerts reach the bot.
- The update timer is enabled by the deploy on both roles. Before its first
  night run, check `tracegate-engine-update status` on each host, and that the
  host can reach the official registries.
- Engine activation restarts engine units in the night window; probes and
  rollback run after each restart.

Validated by the test suite (including the PostgreSQL migration tests), lint,
host checks and the public release privacy check. The supervisor has not yet
run against the real registries or hosts; its first live runs are part of the
acceptance of this release.
