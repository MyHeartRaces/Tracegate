# Tracegate 4.2.2

Re-issue fix, Entry traffic shaping and a Telemt unit guard. No database
migration and no change to issued connections.

- Re-issue keeps the previous revision reachable when the Reality SNI
  changes. The control plane sends `active_reality_snis` (the SNIs of all
  active revisions) with every connection update, and agents register the
  client on each matching grouped Reality inbound. Before this, a previous
  revision on another SNI only worked when its ClientHello was fragmented.
- Entry: the ingress policer is off by default. It dropped packets instead
  of queueing them and stalled transfers. The TX cap (HTB, default
  65 Mbit/s) is unchanged. `AGENT_ENTRY_TRAFFIC_SHAPING_APPLY_INGRESS_POLICING=true`
  restores the policer.
- `tracegate-mtproto@.service` is skipped on hosts without an active Telemt
  artifact instead of failing every 3 s.

## Upgrade notes

- Deploy Endpoint first (control plane and its agent), then Entry. Agents
  on older releases ignore the new field.
- After both hosts run 4.2.2, call `POST /dispatch/reissue-current-revisions`
  once. It re-sends the current revisions with the new field; it does not
  create new revisions.
- Entry hosts that set the policer variable explicitly keep their setting.

Validated by lint, host checks, the public release privacy check and the
shaping and unit-file tests; the full test suite runs in CI.
